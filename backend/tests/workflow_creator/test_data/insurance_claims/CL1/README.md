# CL1 — Residential Kitchen Fire (CLM-2025-08742)

Synthetic data for the **Insurance Claims Investigation** workflow
(`workflows/26_insurance_claims.json`), claim scenario CL1: a legitimate
$180K residential kitchen grease fire (Margaret & Robert Chen, Naperville IL).

There are **two representations of the same claim**, both consistent because the
documents are generated *from* the CSVs:

| Folder | Format | Used by |
|--------|--------|---------|
| `CL1/*.csv` | Flattened CSV (original) | Default test path — runner pastes CSV text into the prompt |
| `CL1/documents/` | Multi-format packet (txt/docx/xlsx/csv/jpg) | `--use-documents` path — realistic "claim folder", text-extracted |

## Document packet (`CL1/documents/`)

Generated by `python build_cl1_evidence.py` (idempotent; regenerates the folder).
Single source of truth = the six `CL1/*.csv` files, so numbers never diverge.

| File | Format | Derived from | Primary consumer agent |
|------|--------|--------------|------------------------|
| `FNOL_intake.txt` | TXT | claim_details.csv | Claims Triage Adjuster |
| `adjuster_notes.txt` | TXT | claim_details + prior_claims | Claims Triage Adjuster |
| `fire_investigation_report.docx` | DOCX | fire_investigation.csv | Triage + Property Damage Assessor |
| `policy_declarations.docx` | DOCX | policy_info.csv | Policy Coverage Analyst |
| `damage_inventory.xlsx` | XLSX | damage_assessment.csv (20 items) | Property Damage Assessor |
| `contractor_estimates.xlsx` | XLSX (Summary + 3 sheets) | contractor_estimates.csv | Property Damage Assessor |
| `prior_claims.csv` | CSV | prior_claims.csv (copy) | Claims Triage Adjuster |
| `evidence/photo_01..07_*.jpg` | JPG + EXIF | damage_assessment rooms | Property Damage Assessor |
| `evidence/evidence_manifest.csv` | CSV | generated | Property Damage Assessor |

### Evidence images

PIL-rendered captioned cards (no image-gen model available), **not photoreal**.
The evidentiary payload is the **EXIF + manifest**, which survive text extraction:

- `DateTimeOriginal` = `2025:01:16 09:24:00` (adjuster inspection, within loss window)
- GPS = `41.74805, -88.16563` (Naperville — matches insured address)
- `Make`/`Model` = Apple iPhone 13; caption embedded in `ImageDescription`

A Property Assessor / Fraud Investigator can reason about date- and GPS-consistency
even though the pixels are synthetic.

## Persona-prompt anti-stall fix (DONE)

The 7 specialist personas in `workflows/26_insurance_claims.json` were hardened with a
**"WORK FROM THE DATA PROVIDED (DO NOT STALL)"** block: they must treat the inline
extracted tables/text as the provided documents, never ask for uploads, never emit
`$[provide]` placeholders or `STATUS: PENDING/INCOMPLETE`, and produce
`STATUS: COMPLETE` immediately (stating labeled assumptions for any genuinely missing
field). PythonTool agents are told to compute on the in-prompt data, not `read_csv()`
file paths. Triage (already correct) and Settlement Writer (synthesizes) were left as-is.

> Redeploy to apply: `python create_workflows.py --update --file workflows/26_insurance_claims.json`
> (`--update` syncs each step-persona's system_prompt.)
